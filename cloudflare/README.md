# Cloudflare hosting (Workers + static assets, free plan)

The same repo runs on Netlify **and** Cloudflare. Nothing under `netlify/functions/`
changes; Cloudflare reuses those handlers through a thin adapter.

| Netlify | Cloudflare |
| --- | --- |
| static publish `.` | Workers static assets (`assets.directory = "."`, filtered by `.assetsignore`) |
| `netlify.toml` / `_redirects` `/api/*` rewrites | `cloudflare/worker.mjs` route table (same paths, also `/.netlify/functions/<name>`) |
| `netlify.toml` `[[headers]]` | `_headers`, generated by `cloudflare/build.mjs` |
| Netlify Blobs (`@netlify/blobs`) | SQLite Durable Object `BlobStoreDO` (`cloudflare/blobs-do.mjs`) via the shim `cloudflare/blobs-d1.mjs` (aliased in `wrangler.jsonc`); D1 also supported |
| `l7in-generated.netlify.app` (generated images) | assets-only Worker `l7in-generated` (`cloudflare/wrangler.generated.jsonc`), served at `/generated/*` of the main Worker via the `GENERATED` service binding |
| `context.waitUntil` background job | job runs inside the POST (no 30 s waitUntil cap); client still polls `/api/jobs/:id` |
| env vars | Worker variables / secrets (`process.env` via `nodejs_compat`) |

Free-plan limits that shaped this:
- **20,000 files per deploy, 25 MiB per file.** The repo has ~27k files, so
  `sketches-meta/`, `generated-meta/` and `sketches/json/` (~14k small JSON files)
  are packed by `cloudflare/build.mjs` into `cf-packs/` and served back at their
  original URLs by `cloudflare/packs.mjs` (byte-identical). Upload is ~13.3k files.
  `js/vendor/ffmpeg/core/ffmpeg-core.wasm` (32 MB) is skipped; videofy-export.js
  already falls back to jsDelivr/unpkg.
- **KV allows only 1,000 writes/day**, and tab presence writes every 10 s per open
  tab, so blobs live in SQLite: a Durable Object by default (works with a token
  that has only Workers Scripts Edit), or D1 if a `DB` binding is added (the D1
  binding wins when present; re-import after switching).
- **100k Worker requests/day.** Static files don't count; `/api/*` calls do
  (one open, visible tab ≈ 8.6k presence heartbeats/day).
- 10 ms CPU per request: fine (handlers mostly wait on network/D1).

## Deploy (GitHub Actions)
`.github/workflows/cloudflare-deploy.yml` runs on every push to `main` (and on
manual "Run workflow"): adapter tests -> `node cloudflare/build.mjs` ->
`wrangler deploy` -> smoke test of `/api/health`. It needs the repo secret
`CLOUDFLARE_DEPLOY_TOKEN` (API token with Workers Scripts Edit on the account;
D1 Edit only if you switch to D1); without it the job skips. Set it without echoing the value, e.g.
`printenv CLOUDFLARE_DEPLOY_TOKEN | gh secret set CLOUDFLARE_DEPLOY_TOKEN`.
Manual deploy from a checkout: `node cloudflare/build.mjs && npx wrangler deploy`.

Secrets (Worker → Settings → Variables and Secrets, type Secret):
`XAI_API_KEY` (or `XAI_API_KEYS`), `CLOUDFLARE_API_TOKEN` (Workers AI),
`POLLINATIONS_API_KEY`, and if used: `XAI_MANAGEMENT_KEY`, `XAI_TEAM_ID`,
`GOOGLE_CLIENT_ID`, `WOMBO_DREAM_API_KEY`, `CLAUDE_MODEL`, `OPENAI_MODEL`, `CF_IMAGE_MODEL`,
`CF_IMAGE_STEPS`, `POLLINATIONS_IMAGE_MODEL`, `POLLINATIONS_TIMEOUT_MS`, `SPELLFORGE_IMAGE_PROVIDER`.
`CLOUDFLARE_ACCOUNT_ID` is a plain var in `wrangler.jsonc`.

The Durable Object is created by the `v1` migration on the first deploy; tables
are created on first use.

## Generated images
`generated/` (6k+ images, ~2.4 GB) is not in git, so the Action does not upload
it. Deploy it from a checkout that has the folder (the PC), before the first
main deploy and whenever new images are added:

    npx wrangler deploy -c cloudflare/wrangler.generated.jsonc

The main Worker serves them at `/generated/*` and injects
`window.GENERATED_ORIGIN = ""` into `/` and `/subscribe`, so `js/app.js`,
`js/transfer.js`, `js/assets-tab.js` and `js/print-shops.js` use same-origin
`/generated/...` on Cloudflare and keep using `https://l7in-generated.netlify.app`
on Netlify (the flag is never set there).

## Move data from Netlify Blobs
Export each store/key with `netlify blobs:get <store> <key> --output <dir>/<file>`
plus a `manifest.json` (`[{store, key, file}]`), then:

    # Durable Object store: set a temporary ADMIN_TOKEN Worker secret, then
    node cloudflare/import-netlify-blobs.mjs <dir> --json > rows.json
    curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" --data-binary @rows.json \
      https://logan7in-art.logan7in.workers.dev/api/_admin/blobs-import
    npx wrangler secret delete ADMIN_TOKEN   # closes the import route again

    # D1 store instead:
    node cloudflare/import-netlify-blobs.mjs <dir> > blobs-import.sql
    npx wrangler d1 execute logan7in-blobs --remote --file blobs-import.sql

## Local test
    node cloudflare/build.mjs
    npx wrangler dev --persist-to ../.wrangler-state   # put secrets in .dev.vars
(Keep `--persist-to` outside the repo. The assets dir is the repo root, so state
written inside it makes `wrangler dev` reload in a loop.)
